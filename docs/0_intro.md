# ВСТУП

## 1. АКТУАЛЬНІСТЬ ТЕМИ
Сучасні розподілені системи та хмарні мікросервісні архітектури висувають критичні вимоги до забезпечення високої доступності, стійкості до відмовостійкості (Fault Tolerance) та мінімізації мережевих затримок (Latency). Традиційні монолітні рішення та стандартні бібліотеки управління станом і координацією часто не здатні забезпечити лінійну масштабованість та детермінований консенсус у гетерогенному середовищі. Розробка власного високоефективного інфраструктурного фреймворку для маршрутизації завдань, розподіленого кешування та синхронізації стану на базі алгоритму Raft є надзвичайно актуальною інженерною задачею, що дозволяє оптимізувати накладні витрати на мережеві взаємодії та підвищити надійність розподілених додатків у реальному часі.

## 2. ОБ'ЄКТ ДОСЛІДЖЕННЯ
Процес функціонування, реплікації стану та обробки транзакційних запитів у розподілених інформаційних системах і вузлах обробки даних.

## 3. ПРЕДМЕТ ДОСЛІДЖЕННЯ
Методи, архітектурні патерни та алгоритми забезпечення консенсусу (Raft), нуль-копіювання серіалізації (Kryo), асинхронної обробки подій (Netty, Reactor) та багаторівневого кешування (Caffeine + RocksDB).

## 4. МЕТА РОБОТИ
Проєктування та розробка легковагового модульного фреймворку для консистентного хешування, розподіленого кешування та маршрутизації завдань, спрямованого на зниження мережевих затримок, забезпечення лінійної масштабованості та гарантованої цілісності даних у розподіленому середовищі.

## 5. ЗАВДАННЯ ПРОЄКТУ
1. Проаналізувати існуючі аналоги, інфраструктурні рішення та протоколи розподіленого консенсусу за стандартом ДСТУ.
2. Обґрунтувати вибір технологічного стеку (Java 21, Spring Boot, Netty, Kryo, Raft).
3. Спроєктувати архітектуру фреймворку із застосуванням UML-діаграм та моделі C4 (Context, Containers, Components).
4. Здійснити алгоритмізацію та реалізацію критичних вузлів фреймворку (транспортний шар, механізми консенсусу та кешування).
5. Проєктувати інтерфейси взаємодії, конфігураційні схеми та Spring Boot Starters для інтеграції в зовнішні системи.
6. Провести інструментальний аудит коду та комплексне тестування (unit, integration testing).
7. Здійснити розгортання, апробацію архітектурних рішень та підготувати звітну документацію.
