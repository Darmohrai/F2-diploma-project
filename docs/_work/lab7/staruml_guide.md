# Діаграма прецедентів у StarUML: покрокова інструкція (≈ 20 хв)

Умова ЛР№7 вимагає CASE-засіб (StarUML / Enterprise Architect / Visual Paradigm), а не Mermaid. Діаграму треба
намалювати руками – так викладач бачить, що ви вмієте працювати з UML-нотацією. Зміст (актори, прецеденти,
зв'язки) уже зафіксовано в `docs/2_design.md`, підрозділ 2.6.1 – переносите його 1:1.

Орієнтир розміщення – `usecase_layout_sketch.png` у цій папці (це **ескіз**, не для здачі).

## 0. Встановлення

1. <https://staruml.io/download> → StarUML 6 / 7 для Windows. Безкоштовної (evaluation) версії достатньо;
   водяний знак на експорті PNG у незареєстрованій версії не з'являється, лише нагадування при збереженні.
2. **File → New**. У Model Explorer праворуч – `Model`.

## 1. Діаграма і межа системи

1. Правою кнопкою на `Model` → **Add Diagram → Use Case Diagram**. Назва: `Kurin – Use Case Diagram`.
2. У палітрі (Toolbox) зліва → **Subject** (прямокутник) → розтягніть на центр полотна, ≈ 60 % ширини.
   Name: `Кластер сервісу з Kurin`.

## 2. Актори

Toolbox → **Actor**, клік на полотні.

**Ліворуч** (зверху вниз):

| Актор | Примітка |
| :--- | :--- |
| `Клієнт застосунку` | |
| `Розробник застосунку` | |
| `Спостерігач стану` | у Properties поставте **isAbstract = true** (ім'я стане курсивом) |
| `Оператор (DevOps)` | під «Спостерігачем», трохи лівіше |
| `Оркестратор (Kubernetes)` | поруч з Оператором |
| `Prometheus` | поруч |
| `Таймер` | унизу; можна стереотип `<<time>>` (Properties → stereotype) |

**Праворуч**: `PostgreSQL`, `Зовнішнє сховище кешу (Redis)`.

## 3. Прецеденти (еліпси всередині Subject)

Toolbox → **Use Case**, клік *всередині* Subject (тоді прецедент належить Subject). Назви – дієслово в
інфінітиві, саме так, як нижче (ID можна писати на початку):

Основні (лівий стовпчик Subject):

- `UC-01 Виконати операцію під розподіленим блокуванням`
- `UC-02 Отримати дані через багаторівневий кеш`
- `UC-03 Змінити дані з інвалідацією кешу`
- `UC-04 Прочитати власний запис з репліки`
- `UC-05 Виконати задачу лідера`
- `UC-06 Виконати одноразову задачу кластера`
- `UC-07 Отримати стан вузла`, під ним `UC-07a Перевірити health-вердикт компонента`,
  `UC-07b Отримати повний стан вузла й модулів`
- `UC-08 Налаштувати координацію анотаціями`

Включені (середній стовпчик): `UC-I1 Зафіксувати команду в журналі Raft`, `UC-I2 Видати маркер огородження`,
`UC-I3 Перевірити рівні кешу L1–L3`, `UC-I4 Вибрати вузол бази даних`, `UC-I5 Перевірити оренду лідера`,
`UC-I6 Перевірити анотації під час старту`.

Розширення (правий стовпчик): `UC-E1 Чекати звільнення блокування`, `UC-E2 Компенсувати невідомий результат`,
`UC-E3 Відхилити запис власника з простроченим маркером`, `UC-E4 Завантажити значення з джерела з single flight`,
`UC-E5 Обійти рівень L3 за розімкненого вимикача`, `UC-E6 Перенаправити читання на primary`.

## 4. Зв'язки

| Що | Інструмент Toolbox | Звідки → куди |
| :--- | :--- | :--- |
| Направлена асоціація | **Directed Association** | Клієнт → UC-01, UC-02, UC-03, UC-04; Розробник → UC-08; Спостерігач стану → UC-07; Таймер → UC-05, UC-06 |
| Асоціація з вторинними | **Directed Association** | UC-01 → PostgreSQL; UC-02 → PostgreSQL, UC-02 → Redis; UC-03 → PostgreSQL, UC-03 → Redis; UC-04 → PostgreSQL |
| Узагальнення акторів | **Generalization** (стрілка з порожнім трикутником **від нащадка до предка**) | Оператор → Спостерігач стану; Оркестратор → Спостерігач стану; Prometheus → Спостерігач стану |
| Узагальнення прецедентів | **Generalization** | UC-07a → UC-07; UC-07b → UC-07 |
| `<<include>>` (обов'язкове, DRY) | **Include** (стрілка **від базового до включеного**) | UC-01 → UC-I1, UC-01 → UC-I2; UC-03 → UC-I1; UC-06 → UC-I1; UC-02 → UC-I3; UC-03 → UC-I4; UC-04 → UC-I4; UC-05 → UC-I5; UC-08 → UC-I6 |
| `<<extend>>` (опціональне) | **Extend** (стрілка **від розширення до базового**) | UC-E1 → UC-01; UC-E2 → UC-01; UC-E3 → UC-01; UC-E4 → UC-02; UC-E5 → UC-02; UC-E6 → UC-04 |

Напрямки – найчастіша помилка на захисті: **include** – «базовий завжди викликає включений» (стрілка від
базового); **extend** – «розширення інколи доповнює базовий» (стрілка від розширення до базового).

**Точки розширення (для повних балів).** Виділіть UC-01 → Properties → **Extension Points → +**:
`ключ зайнятий, waitTimeout > 0`, `тайм-аут або розрив після надсилання`, `ресурс бачить більший маркер`.
Для UC-02: `промах у всіх рівнях`, `5 відмов L3 поспіль`. Для UC-04: `репліка відстає від маркера`.
Потім у кожного Extend → Properties → **condition** – той самий текст.

## 5. Охайність

- Format → **Auto Resize** для еліпсів; вирівнювання – виділити групу → **Align Left / Top**.
- Лінії без перетинів, де можливо: Format → Line Style → **Rectilinear** або **Oblique**.
- Перевірка: у Model Explorer усі прецеденти мають бути *всередині* Subject (вкладені під ним).

## 7. Що сказати на захисті (20 секунд)

«Межа – кластер сервісу з Kurin; ліворуч первинні актори, серед них абстрактний Спостерігач стану з трьома
нащадками – це ієрархія прав доступу до Actuator. Праворуч вторинні – PostgreSQL і Redis. Include – спільний
код: усі зміни стану йдуть через фіксацію команди в журналі Raft. Extend – edge cases: очікування,
компенсація невідомого результату, відхилення застарілого маркера; кожен extend має точку розширення з
умовою».
