### 3.3 Важливо про StarUML

У твоєму StarUML **закінчився trial** – програма працює в режимі Viewer. Через це:

- модель `.mdj` – повноцінна, відкривається в StarUML, усе редагується (якщо є ліцензія);
- PNG, експортований у режимі Viewer, має **блідий водяний знак «UNREGISTERED»** на полях поза прямокутником
  системи (на самій діаграмі його не видно, бо межа системи залита білим).

Як отримати чистий PNG (обери одне):

1. Ліцензія StarUML (є знижка для студентів) → `File → Open` → `docs\uml\kurin-use-cases.mdj` →
   `File → Export Diagram As → PNG` → зберегти поверх `docs\uml\kurin-use-cases.png` → замінити картинку в .docx
   (2.6.1, Рисунок 2.9) і в Notion → `git add docs/uml/kurin-use-cases.png "docs/F2_Diploma_Chapters1-2_Дармограй.docx"`
   → `git commit -m "docs: re-export the use case diagram without watermark"` → `git push`.
2. Залишити як є і на захисті сказати чесно: «модель зроблена в StarUML, ліцензія trial закінчилась, тому на
   полях експорту водяний знак». Модель `.mdj` – головний артефакт CASE-засобу.

## 4. Use Case діаграма – що на ній і як пояснити

**Межа системи** – «Кластер сервісу з Kurin» (прямокутник). Усередині – 22 прецеденти, зовні – 9 акторів.

**Актори.**

| Актор | Тип | З чим пов'язаний |
| :--- | :--- | :--- |
| Клієнт застосунку | первинний | UC-01, UC-02, UC-03, UC-04 |
| Розробник застосунку | первинний | UC-08 (налаштувати координацію анотаціями) |
| Таймер `«time»` | первинний | UC-05 (задача лідера), UC-06 (одноразова задача) |
| *Спостерігач стану* (курсив = **абстрактний**) | первинний | UC-07 (стан вузла) |
| Оператор (DevOps), Оркестратор (Kubernetes), Prometheus | нащадки Спостерігача (узагальнення – трикутник до предка) | успадковують доступ до UC-07 |
| PostgreSQL, Зовнішнє сховище кешу (Redis) | вторинні (праворуч) | UC-01–UC-04 звертаються до них |

**Зв'язки – найчастіше питання на захисті.**

- `«include»` – базовий прецедент **завжди** викликає включений (спільний код, DRY). Стрілка **від базового до
  включеного**. Приклад: UC-01, UC-03, UC-06 → UC-I1 «Зафіксувати команду в журналі Raft» – будь-яка зміна стану
  йде через журнал.
- `«extend»` – розширення **інколи** доповнює базовий за умови. Стрілка **від розширення до базового**. Кожен
  extend має **точку розширення** (вписана під еліпсом базового прецедента) і **умову** (`condition`).
  Приклад: UC-E1 «Чекати звільнення блокування» → UC-01, умова «ключ зайнятий, waitTimeout > 0».
- Узагальнення прецедентів: UC-07a (health-вердикт) і UC-07b (повний стан) – окремі випадки UC-07.

**20-секундна відповідь:** «Межа – кластер сервісу з Kurin; ліворуч первинні актори, серед них абстрактний
Спостерігач стану з трьома нащадками – це ієрархія доступу до Actuator. Праворуч вторинні – PostgreSQL і Redis.
Include – спільний код: усі зміни стану йдуть через фіксацію команди в журналі Raft. Extend – edge cases:
очікування, компенсація невідомого результату, відхилення застарілого маркера; кожен extend має точку розширення
з умовою.»

**Специфікації сценаріїв** – у 2.6.2 (UC-01, розподілене блокування з маркером огородження) і 2.6.3 (UC-02,
багаторівневий кеш). Структура кожної: Передумови (продуктові + інфраструктурні) → Happy Path до рівня викликів →
Постумови → Alternative Flows (мета досягається інакше) → Exception Flows (мета недосяжна, безпечний стан).

## 5. Як працює Docs Quality Gate (Завдання 5)

1. `.markdownlint.jsonc` – **правила** (довжина рядка 120, стиль списків, заголовків, таблиць тощо).
2. `.markdownlint-cli2.jsonc` – **які файли** перевіряти: `docs/**/*.md`, крім `docs/_work/**` (чернетки, логи)
   і згенерованого `docs/KURIN_TECHNICAL_GUIDE.md`.
3. `.github/workflows/docs-linter.yml` – GitHub Actions: на кожен Pull Request у `master`, що змінює `docs/`,
   запускає `npx markdownlint-cli2@0.23.2` на Ubuntu з Node 22. Версія **закріплена**, щоб новий реліз лінтера з
   новими правилами не зробив зелений PR червоним без змін у документах.
4. Результат – галочка в PR: зелена ✓ = 0 помилок; червоний ✗ = є помилки (список `файл:рядок правило` у логах).

Лінтер перевіряє лише **закомічені** файли. Твої локальні незакомічені `docs/KURIN_TECHNICAL_GUIDE.md`,
`docs/paper/Kurin_tezy.md` на CI не впливають.

## 10. Якщо щось пішло не так

| Симптом | Що робити |
| :--- | :--- |
| `git push` питає логін/пароль | GitHub більше не приймає пароль – увійди через вікно Git Credential Manager (браузер) або використай токен |
| `rejected (fetch first)` | хтось змінив гілку на GitHub: `git pull --rebase origin feature/lab7-docs-quality-gate`, потім `git push` |
| Галочки взагалі немає | у PR немає змін у `docs/` або в `.github/workflows/docs-linter.yml` – workflow фільтрує за шляхами; або Actions вимкнено в Settings → Actions → General |
