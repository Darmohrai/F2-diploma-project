# Проєктування та програмна реалізація інфраструктурного каркаса для забезпечення консенсусу в розподілених системах на базі алгоритму Raft
*Design and Implementation of an Infrastructure Framework for Consensus in Distributed Systems Based on the Raft Algorithm*

## Актуальність та проблематика
Забезпечення строгих гарантій узгодженості даних та відмовостійкості у Cloud-Native середовищах вимагає ефективних інструментів. Існуючі рішення (ZooKeeper, etcd) є важковаговими. Складність полягає у забезпеченні високопродуктивного неблокуючого мережевого обміну, усуненні стану гонитви та мінімізації навантаження на Garbage Collector.

## Ідея продукту
Розробка вбудованого (embeddable) інфраструктурного фреймворку для Java-додатків, що абстрагує складність мережевої синхронізації та надає API для створення кластеризованих сервісів на основі Raft. Відповідно до встановлених архітектурних меж, фреймворк проєктується для роботи в умовах **статичної топології вузлів**. Мережеві адреси та ідентифікатори всіх вузлів-учасників (Peers) фіксуються на етапі початкового завантаження (Bootstrap). Це усуває необхідність імплементації ресурсоємних протоколів спільного консенсусу (Joint Consensus) для додавання/видалення нод «на льоту» та гарантує стабільний і передбачуваний розрахунок кворуму.

## Детальний опис функціоналу (Core Features)
1. **Асинхронний мережевий транспортний шар (Netty):** Реалізація неблокуючої взаємодії між наперед заданим пулом вузлів кластера з мультиплексуванням TCP-з'єднань.
2. **Zero-Copy серіалізація (Kryo):** Механізм бінарного кодування повідомлень безпосередньо в мережеві буфери пам'яті.
3. **Ізоляція стану на базі моделі Акторів (Lock-free Mailbox):** Забезпечення суворої послідовності виконання транзакцій для окремих вузлів без використання традиційних механізмів блокування.
4. **Статичне управління кворумом (Static Peer Registry):** Механізм ініціалізації та валідації незмінного списку учасників кластера, що дозволяє миттєво розраховувати необхідну більшість голосів (Majority/Quorum) для прийняття рішень.
5. **Алгоритм виборів лідера (Raft Leader Election):** Реалізація фази переходу станів вузла (Follower $\rightarrow$ Candidate $\rightarrow$ Leader) в умовах фіксованої топології з використанням детермінованих таймаутів (Hashed Wheel Timer).
6. **Реплікація логів з гарантією цілісності:** Механізм розсилки транзакцій від лідера до статичного списку послідовників із гарантією фіксації записів (Commit).
7. **Експорт телеметрії кластера (Observability):** Інтеграція OpenTelemetry для моніторингу затримок між вузлами.

## Інструментарій та технологічний стек
* **Мови програмування:** Java.
* **Мережевий фреймворк:** Netty (асинхронний I/O).
* **Бібліотека серіалізації:** Kryo (Zero-Copy серіалізація).
* **Архітектурні патерни:** Actor Model (Lock-free Mailbox), Reactor, Dependency Injection Container.
* **DevOps, тестування та інфраструктура:** Apache Maven, JUnit 5, Testcontainers (CI/CD інтеграційні тести розподілених сценаріїв), Kubernetes (оркестрація кластера), GitHub Actions, SonarQube, OpenTelemetry.
